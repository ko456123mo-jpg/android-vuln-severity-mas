## 4) الأمن — ما فُرض فعلياً (يُختبر، لا يُوصف فقط)

| الضبط | السلوك المقيس | الاختبار |
|---|---|---|
| ترويسات أمنية | على كل استجابة، **بما فيها 500** (المعالج العام خارج مكدّس الوسائط) | `TestSecurityHeaders::test_headers_on_500` |
| HSTS | في الإنتاج/HTTPS فقط | نفس الملف |
| حدّ المعدل | 60/دقيقة لكل IP · 429 بصيغة موحّدة + `Retry-After` + `X-RateLimit-*` · `/health` و`OPTIONS` معفاة | `TestRateLimit` |
| الأسرار | `MAS_SECRET_KEY` ≥ 32 · قائمة قيم ضعيفة · **RuntimeError في الإنتاج** لا تحذير | `TestSecretsValidation` |
| المصادقة | رفض منتهٍ/مزوّر/`alg=none`/مستخدم محذوف بـ 401 + `WWW-Authenticate` | `TestJWT` |
| التفويض | ملكية على السلسلة كاملة · مدير كامل · مراجع لدوره فقط · مورد يتيم ⇒ 403 (فشل مغلق) | `TestAuthz` |
| الرفع | امتداد/حجم/بصمة · لا مسارات خروج عن `data/apks` | `TestUploads` |
| الحقن | SQL (استعلامات مُعاملة) · حقن برومبت (درع حتمي) | `TestInjection`, `TestSQLi` |

## 5) الحاويات — ما تحقق فعلياً وما تخطّيناه

- **تحقق ساكن كامل:** تعريفات `docker-compose.yml` صحيحة YAML بثلاث خدمات إلزامية
  (`api`, `ui`, `mobsf`) + `ollama` اختياري، و`healthcheck` لكل خدمة، وصورتان
  متعددتا المراحل بمستخدم غير root و`HEALTHCHECK`، وبلا `privileged` وبلا
  `docker.sock` (فحص آلي).
- **ما لم يُنفَّذ هنا بصدق:** `docker compose build/up` — لأن `docker` غير مثبّت في
  بيئة التسليم. البند يظهر في الفحص النهائي بصياغة صريحة (تحقق ساكن) لا كنجاح وهمي.
