# تصليب الأمن / Security Hardening — المرحلة 8

**الإصدار:** v1.0.0 · **آخر مراجعة:** 2026-10-12
**المرجع الآلي:** `tests/security/test_security.py` (38 اختباراً) + `tests/chaos/test_resilience.py` (11 اختباراً)

هذا المستند يسجّل **كل قرار أمني** في النظام: ما نُفّذ، ولماذا، وبأي بديل رُفض، وأين
يُختبر. لا يعتمد أي بند هنا على «نية» غير مُختبرة.

---

## 1) نموذج التهديد ونطاق الحماية

النظام تطبيق **أحادي المستأجر (single-tenant)** يعمل داخل مؤسسة واحدة: خادم FastAPI
وواجهة Streamlit وقاعدة SQLite، مع أدوات فحص (jadx/MobSF/Frida/Objection) و**مزوّدي
نماذج خارجيين** (Groq/Gemini/Ollama).

الأصول المحميّة، والأخطار الرئيسة، والضوابط:

| الأصل | الخطر | الضابط (المرحلة 8) |
|---|---|---|
| مخرجات الأدوات (نصوص APK) | حقن برومبت يوجّه الـ LLM | `core/guardrails/injection_shield.py` — 5 طبقات + تسجيل `agent_logs` |
| API (42 نقطة) | تجاوز مصادقة/تفويض، إغراق، تسريب | JWT + تفويض ملكية + حدّ معدل + ترويسات + أخطاء موحّدة |
| موارد المشاريع/الفحوص/التقارير | IDOR (قراءة موارد مستخدم آخر) | `api/authz.py` — سلسلة ملكية كاملة |
| قاعدة البيانات | حقن SQL، قفل، فساد | استعلامات SQLAlchemy مُعامَلة، WAL + busy_timeout، soft delete |
| الأسرار (مفاتيح المزوّدين، مفتاح JWT) | تسريب، قيم افتراضية ضعيفة | `core/security/secrets.py` + `.env` + فحص إقلاع |
| ملفات APK المرفوعة | اجتياز مسار / إغراق القرص | تخزين ببصمة SHA-256 + تحقق امتداد/حجم في `api/routers/applications.py` |

خارج النطاق صراحةً (موثّق في §9): تشفير القرص، عزل الشبكة، WAF، SSO، إبطال التوكنات.

## 2) المصادقة — JWT كامل (`api/auth.py`)

| القرار | القيمة | السبب | البديل المرفوض |
|---|---|---|---|
| التوقيع | HS256 | متماثل يكفي لعملية واحدة؛ لا بنية تحتية مفاتيح | RS256 (تعقيد إدارة مفاتيح بلا فائدة هنا) |
| مدة التوكن | 60 دقيقة (من `settings.yaml`) | توازن بين التجربة وسرعة الانتهاء | توكن دائم (أُرفض: يمنع الانتهاء الطبيعي) |
| `sub` | `str(users.id)` | يُقرأ المستخدم من القاعدة في كل طلب | تضمين الدور/الصلاحيات في التوكن (يتيح تصعيداً بعد تغيير الدور) |
| مفتاح التوقيع | `MAS_SECRET_KEY` ← `settings.yaml` | تجاوز بيئي للنشر بلا تعديل كود | مفتاح مُثبّت في الكود |
| كلمات المرور | bcrypt خام (72 بايت مقصوصة) | توافق passlib↔bcrypt مكسور (موثّق) | passlib (خطأ قراءة إصدار مع bcrypt≥4) |
| حسابات محذوفة | 401 فوري (قراءة القاعدة كل طلب) | إبطال فوري بلا قائمة سوداء | قائمة إبطال (تحتاج حالة مشتركة بين العمليات) |

**اختبارات:** توكن منتهٍ، موقّع بمفتاح خاطئ، `alg=none` (algorithm confusion)،
مشوّه، لمستخدم محذوف، وغياب الترويسة ← 401 (`TestJwtAuthentication`).

**إصلاح عيب حقيقي (المرحلة 8):** المعالج المخصّص للاستثناءات في `api/main.py` كان
يُرجع `JSONResponse` **بلا** ترويسات الاستثناء، فتفقد استجابات 401 ترويسة
`WWW-Authenticate` التي يعتمد عليها العملاء والوسطاء. الإصلاح:
`headers=getattr(exc, "headers", None)` + اختبار مباشر.

## 3) التفويض — سلسلة الملكية (`api/authz.py`)

**الوضع قبل المرحلة 8 (موثّق كعيب):** كل مسار كان محمياً بالمصادقة فقط؛ أي مستخدم
مُصادَق يستطيع قراءة/تعديل/حذف أي مشروع وتطبيق وفحص **وتنزيل تقارير غيره** (IDOR).
لم يكن هناك أي فحص ملكية في الكود (`grep owner_id api/routers` ⇒ فلترة قائمة فقط).

### السياسة المعتمدة

السلسلة: `projects.owner_id ← applications.project_id ← scans.application_id ←
vulnerabilities.application_id ← assessments.vulnerability_id`.

1. **admin** — وصول كامل (تشغيل وتشخيص النظام). يُطبَّق بـ `require_admin` حيث يكون
   المورد تجميعياً على كل النظام: `/dashboard/*`، والتسجيل `POST /auth/register`.
2. **owner** — يصل إلى ما ينتهي في سلسلته إلى مشروع يملكه (`owner_id == user.id`).
3. **reviewer** — يصل إلى حلقة المراجعة البشرية (`/reviews/*`, `/assessments` قوائم
   الفرز) بغض النظر عن الملكية: هذا دوره الوظيفي في القياس (المرحلة 7). لا يمنحه
   ذلك أي صلاحية على كتابة المشاريع (مُختبر: 403 على `GET /projects/{id}`).
4. **analyst** (الافتراضي عند التسجيل) — لا يرى إلا مشاريعه.
5. **مورد بلا مالك** (`owner_id IS NULL`) أو يتيم السلسلة — **fail-closed**: يُرفض
   لغير admin. هذه صفوف أنشأتها سكربتات/اختبارات، وليست مساراً إنتاجياً (الـ API
   يضبط `owner_id` دائماً عند الإنشاء).

### قرارات فرعية

| القرار | الاختيار | السبب | البديل المرفوض |
|---|---|---|---|
| رمز الرفض | **403** للموجود غير المملوك | التطبيق أحادي المستأجر بمعرّفات تسلسلية أصلاً؛ إخفاء الوجود يضلّل المستخدم الشرعي | 404 دائماً (إخفاء الوجود — يُستعمل في أنظمة متعددة المستأجرين) |
| القوائم | تُصفّى بـ `owned_project_ids/owned_application_ids` | منع التسريب بالترقيم لا بالمعرّف فقط | إرجاع الكل مع 403 عند التفاصيل (تسريب بيانات وصفية) |
| لوحة المعلومات | admin فقط | تجميعات على كل النظام بلا تصفية مالك في SQL | تصفية تجميعية لكل مستخدم (تغيير كبير في SQL المرحلة 6) |
| حلقة المراجعة | admin/reviewer | دور المراجعة يعمل عبر المشاريع في تصميم المرحلة 5 | حصرها بمالك المشروع (يُعطّل سيناريو القياس البشري) |
| التسجيل | admin فقط (كان كذلك) | إبقاء سطح إنشاء الحسابات مغلقاً | تسجيل مفتوح |

**التغطية الاختبارية:** `TestCrossUserAuthorization` (9 اختبارات): 403 على
مشروع/تطبيق/فحص/تقرير، صفر ظهور في القوائم، reviewer يمرّ في الحلقة ويفشل في
المشاريع، admin يمرّ، ومشروع بلا مالك يُرفض للمحلل.

## 4) حدّ معدل الطلبات (`core/security/rate_limiter.py`)

| البند | القيمة |
|---|---|
| الخوارزمية | نافذة انزلاقية بـ `deque` طوابع زمنية لكل مفتاح (بلا Redis) |
| المفتاح | أول IP في `X-Forwarded-For` وإلا `request.client.host` |
| الحد الافتراضي | **60 طلباً/دقيقة/IP** (`MAS_RATE_LIMIT_PER_MINUTE`) |
| الإعفاءات | `/health`, `/docs`, `/openapi.json`, `/redoc`, وكل `OPTIONS` |
| الاستجابة | 429 بصيغة موحّدة `{detail, error:"rate_limited", retry_after}` + `Retry-After` |
| الترويسات المضافة | `X-RateLimit-Limit`, `X-RateLimit-Remaining` |
| التزامن | `threading.Lock` حول المحاسب (آمن لخيوط uvicorn) |

**قرارات:** الإعفاء الكامل للفحص الصحي لأن حاويات Docker ووسطاء التحميل تفحصه كل
ثوانٍ، وحجبها يجعل الخدمة تُعلَن «غير صحية». تعطيل الحد في الاختبارات الآلية يتم
بمتغيّر بيئة صريح (`MAS_RATE_LIMIT_ENABLED=0` في `tests/conftest.py`) **واختبار
الأمن يعيد تفعيله بحدود صغيرة (3/دقيقة)** — فلا يُخفى السلوك الإنتاجي خلف «وضع
اختبار» دائم.

**حدّ معروف وموثّق:** المحاسب في الذاكرة ⇒ لكل عملية حدّها؛ عند التوسع الأفقي
يجب الانتقال إلى Redis (خطة v2). ويعني ذلك أيضاً أن إعادة تشغيل العملية تُصفّر العدّاد.

## 5) الترويسات الأمنية (`core/security/headers.py`)

تُلحق `SecurityHeadersMiddleware` على كل استجابة: `X-Content-Type-Options: nosniff`,
`X-Frame-Options: DENY`, `X-XSS-Protection: 1; mode=block`, `Referrer-Policy: no-referrer`,
`Permissions-Policy` (تعطيل الكاميرا/الميكروفون/الموقع/الدفع), و
`Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'`.

**HSTS شرطي:** `Strict-Transport-Security` يُرسل فقط عند `MAS_ENV=production` أو
`MAS_HSTS=1` أو طلب HTTPS فعلي (`request.url.scheme == "https"`). السبب: إرسال HSTS
على HTTP محلي يُقفل المتصفح على HTTPS لغير موجود في التطوير المحلي.

**إصلاح عيب حقيقي (المرحلة 8):** استجابة **500** لم تكن تحمل الترويسات. السبب دقيق
وموثّق: في Starlette يُنفَّذ معالج `Exception` العام داخل `ServerErrorMiddleware`
**خارج** مكدّس الوسائط المُضافة بـ `add_middleware`، فلا تمر استجابته عبر
`SecurityHeadersMiddleware`. الحل المُختار: `with_security_headers(response, request)`
تُستدعى صراحةً في معالجات 4xx/5xx الثلاثة (بديل مرفوض: `Subclassing ServerErrorMiddleware`
— يعتمد على تفاصيل داخلية غير مستقرة). الاختبار: `test_error_detail_never_leaks_internals`
يفحص الترويسات على 500، وكذلك 429 و403 و404 و422.

## 6) التحقق من الأسرار عند الإقلاع (`core/security/secrets.py`)

`validate_secrets()` يفحص 8 بنود: وجود `MAS_SECRET_KEY` وطوله (≥ 32) وقيمته غير
ضعيفة/معروفة، شكل مفاتيح المزوّدين (`GROQ_API_KEY` بـ `gsk_`, `sk-ant-`, `AIza…`,
`sk-…`) عند وجودها، قوة كلمة مرور المدير الافتراضية، مسار قاعدة البيانات في
الإنتاج، وضبط `MAS_CORS_ORIGINS`.

| البيئة | خطأ (error) | تحذير (warning) |
|---|---|---|
| تطوير (`MAS_ENV` غير production) | — | يُسجَّل ويُطبع، التطبيق يعمل |
| إنتاج | `assert_secrets_or_exit()` يرفع `RuntimeError` **يوقف الإقلاع** | يُسجَّل فقط |

**قرارات:** لا تُطبع قيم الأسرار أبداً في التقرير (يُختبر: `mas-dev-secret` لا يظهر
في الملخّص)، والقيمة الافتراضية التطويرية تبقى مسموحة في التطوير فقط
(`mas-dev-secret-key-change-in-production` مرفوضة في الإنتاج — مُختبر).
الأخطاء لا تُخفى: `RuntimeError` برسالة صريحة «أوقف الإقلاع» + قائمة الأسباب.

## 7) حقن البرومبت — درع الحدود (`core/guardrails/injection_shield.py`)

كل مخرجات الأدوات بيانات غير موثوقة (أسماء أصناف، نصوص، تعليقات قد تحمل تعليمات).
الطبقات بالترتيب:

0. **تطبيع Unicode NFKC + إزالة أحرف zero-width** (`\u200B…\uFEFF`) — مقاومة التمويه.
1. **فك كتل Base64 الطويلة** (≥ 120 حرفاً) ومسح الناتج بالأنماط — مقاومة التهريب المُرمّز.
2. **17 نمطاً معروفاً** (عربي/إنجليزي): «تجاهل التعليمات السابقة»، «ignore all previous
   instructions»، «reveal the system prompt»، «تظاهر بأنك»، وسوم `<system>`… إلخ.
3. **إزالة أحرف التحكم + استبدال** بوسم `[تمت-إزالة-محتوى-مشبوه/REDACTED-SUSPICIOUS]`.
4. **العزل** `wrap_untrusted()` — وسوم بيانات + **Canary Token** عشوائي في الحدّين
   لكشف أي تسرّب سياق.

كل كشف يُسجَّل في `agent_logs` (`injection_shield` / `injection_detected:<tool>`)
بأفضل جهد (فشل التسجيل لا يوقف الفحص) — **مُختبر** في
`test_injection_attempt_is_logged_in_agent_logs`.

## 8) مدخلات الملفات وقاعدة البيانات

| البند | الضابط | الاختبار |
|---|---|---|
| اجتياز المسار | اسم الملف لا يدخل مسار التخزين إطلاقاً: يُخزَّن `data/apks/<sha256>.apk` | اسم `../../../../etc/passwd.apk` ⇒ الملف داخل `APKS_DIR` حصراً |
| امتداد/حجم | `.apk` فقط، ورفض الفارغ (400) والمتجاوز (`MAX_APK_BYTES` ⇒ 413) | `test_upload_rejects_*` |
| صيغ التقارير | **قائمة بيضاء** ست صيغ؛ أي مسار/امتداد آخر ⇒ 422 | `test_download_format_whitelist_blocks_traversal` |
| بصمة APK | `UNIQUE(applications.sha256)` على مستوى النظام | — |
| تكرار البصمة لمستخدم آخر | **409 موحّد بلا أي بيانات** عن التطبيق أو مالكه (كان يُرجع الصف كاملاً ⇒ تسريب) | `test_hash_dedup_cannot_leak_another_users_application` |
| حقن SQL | كل الاستعلامات عبر SQLAlchemy ORM/مُعامَلة؛ لا سلاسل SQL مبنية يدوياً | حمولات الحقن في الدخول والحقول والمعاملات المُنمَّطة |
| سلامة البيانات | قيود `CHECK` للحالات/الفئات + soft delete + WAL + `busy_timeout` | `tests/chaos` (قفل القاعدة) |
| سجل التدقيق | `agent_logs` لكل أداة/وكيل + محاولات الحقن | `tests/unit/test_logging` |

**مقايضة موثّقة:** منع التكرار بالبصمة يكشف — بحكم القيد — أن ملفاً بعينه معروف
للنظام (409). قُبِل هذا لأن القيد أصيل في المخطط ولأن التطبيق أحادي المستأجر،
ومقابله **لا يُعاد أي حقل** من السجل القائم. البديل المرفوض: توليد بصمة مركّبة
بالمشروع (يُفقد خاصية «APK واحد = تحليل واحد» في القياس).

## 9) عيوب حقيقية اكتشفتها اختبارات المرحلة 8 (وأُصلحت)

الاختبارات كُتبت أولاً ثم كشفت السلوك الفعلي؛ هذه القائمة هي أثر ذلك (كل عيب هنا
له اختبار انحدار دائم):

| # | العيب | الأثر الأمني/الوظيفي | الإصلاح | الاختبار |
|---|---|---|---|---|
| 1 | لا تفويض ملكية في أي مسار | IDOR كامل: أي مستخدم يقرأ/يحذف موارد غيره | `api/authz.py` + ربط المسارات | `TestCrossUserAuthorization` |
| 2 | 500 بلا ترويسات أمنية | استجابة خطأ بلا تحصين (CSP/nosniff) | `with_security_headers` في المعالجات | `test_error_detail_never_leaks_internals` |
| 3 | `WWW-Authenticate` يُسقط من 401 | كسر عملاء يعتمدون الترويسة | تمرير `exc.headers` | `test_missing_token_rejected_*` |
| 4 | منع التكرار بالبصمة يُرجع صف مشروع آخر (200) | تسريب بيانات تطبيق مستخدم آخر | 409 بلا بيانات | `test_hash_dedup_cannot_leak_*` |
| 5 | `errors` تُستبدَل في عقد المراحل (orchestrator/extractor/finalize) | **فقدان صامت** لأخطاء الأدوات (فشل MobSF لا يظهر) | دمج `list(state.errors) + errors` في أربع عقد | `test_mobsf_timeout_scan_completes_partial` |

العيب 5 درسٌ من المرحلة 7 («لا تبتلع الاستثناءات بصمت») مكرَّر في مبدأ *تجميع
الحالة*: أي عقدة تُرجع حقلاً تراكمياً يجب أن تُدمج لا تُستبدل.

## 10) تشغيل آمن — قائمة الإنتاج

```bash
MAS_ENV=production \
MAS_SECRET_KEY="$(python -c 'import secrets;print(secrets.token_urlsafe(48))')" \
MAS_ADMIN_PASSWORD='<كلمة مرور قوية>' \
MAS_CORS_ORIGINS='https://console.example.org' \
MAS_RATE_LIMIT_PER_MINUTE=120 \
docker compose up -d api ui
```

- `.env` غير المُدرَج في Git (`.gitignore` + `.dockerignore`) — لا أسرار في الكود.
- MobSF/Yadx/Frida داخل الشبكة الداخلية فقط (`expose` لا `ports` لـ MobSF).
- التفاصيل التشغيلية الكاملة في `docs/user_manual.md` و`docs/deployment_notes.md`.

## 11) ما لم يُنفَّذ عن قصد (خطة v2)

| البند | السبب | الترقية المقترحة |
|---|---|---|
| إبطال التوكنات (logout فعلي) | JWT بلا حالة + عملية واحدة | جدول `token_blacklist` أو توكنات قصيرة + refresh |
| حدّ معدل موزّع | نشر أحادي العملية | Redis + `slowapi`/بوابة API |
| OAuth2/SSO + تدوير مفاتيح | خارج نطاق المشروع العلمي | OIDC مع مزوّد الهوية الجامعي |
| تشفير القاعدة في الراحة | SQLite محلي على قرص مُدار | SQLCipher أو تشفير القرص |
| WAF/حماية DDoS | مسؤولية طبقة النشر | WAF أمام الخدمة |
| فصل صلاحيات قاعدة البيانات | مستخدم واحد للتطبيق | مستخدم قراءة فقط للتقارير |
| ضبط CSP لصفحات Streamlit | الواجهة تُقدَّم من Streamlit نفسه لا من API | CSP مخصّص عبر عكس الوكيل |

جميع بنود هذا المستند مُختبرة آلياً أو موثّقة كخارج نطاق؛ لا بند «نظري».
