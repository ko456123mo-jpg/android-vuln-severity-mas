# ملاحظات الإصدار v1.0.0 — Android Vulnerability Severity MAS

**تاريخ الإصدار:** 2026-10-12 · **الترخيص:** MIT · **التوافق:** Python ≥ 3.11

---

## 1) ما هذا النظام؟

نظام **متعدد الوكلاء (5 وكلاء)** يقيّم خطورة ثغرات تطبيقات أندرويد وفق
**OWASP MASVS**، من رفع ملف APK إلى تقريرين جاهزين (فني إنجليزي وتنفيذي عربي).
الفرق الجوهري عن أنظمة «صندوق أسود»: **كل رقم في النظام قابل للتتبع** إلى معادلة
في الكود أو صف في قاعدة البيانات، وكل قرار تصميمي موثّق، ولا يُنشر أي رقم تجريبي
قبل تعبئة الحقيقة المرجعية يدوياً.

## 3) أبرز ما في الإصدار

### 3.1 خط أنابيب موثّق بالكامل
`orchestrator → أدوات (jadx/MobSF/Frida/Objection) → extractor → scorer →
reviewer → persist_scores → reporter → finalize`، مع حفظ حالة قابل للاستئناف
(LangGraph + SqliteSaver) وتدهور رشيق: فشل أداة واحدة لا يُسقط الفحص (يُسجَّل في
`sanitized errors` ويُكمل).

### 3.2 معادلة خطورة شفّافة
`final = 0.6·base + 0.2·context + 0.2·evidence` — تُنشر المكوّنات كاملة في كل
تقييم (`base_score`, `context_score`, `evidence_score`, `confidence_factor`)
ومعها `rationale` نصي، ويُخزَّن إصدار القاعدة مع كل فحص لإعادة الإنتاج.

### 3.3 حلقة مراجعة بشرية (HITL) مع تعلّم
كل تصحيح بشري يُسجَّل في `corrections` ويولّد **تلقائياً** `feedback_examples`
تُستخدم كأمثلة قليلة (Few-Shot) في الاستخلاص اللاحق. **الثابت:** `final_score`
لا يُعدَّل أبداً بعد الحساب — لا بالمراجعة الآلية ولا بالبشرية (مُختبر).

### 3.4 RAG يعمل بلا إنترنت
`EmbeddingEngine` بأربع خلفيات، مع تراجع تلقائي إلى TF-IDF **مسجَّل السبب**
(`fallback_reason`)، ومخزن متجهات على SQLite (`sqlite-vec` أو بديل python).
الجودة مُتحقَّق منها يدوياً ومثبّتة كاختبار انحدار (4 استعلامات أمنية ← النمط
الصحيح في المرتبة الأولى).

### 3.5 تصليب أمني متكامل (المرحلة 8)
JWT كامل + **تفويض ملكية** على سلسلة الموارد + حدّ معدل + ترويسات أمنية على كل
استجابة + تحقق أسرار عند الإقلاع + درع حقن برومبت. التفاصيل: `docs/security_hardening.md`.

### 3.6 نشر بحاويات
`docker compose up -d` يُشغّل api (8000) + ui (8501) + MobSF **على الشبكة الداخلية
فقط** + Ollama اختياري، بصور multi-stage ومستخدم غير جذري وفحوص صحة.

## 4) الابتكارات القابلة للنشر (خمسة)

1. **معادلة خطورة مركّبة قابلة للتتبع** تربط فئة MASVS بسياق التطبيق بجودة الأدلة،
   وتُخزَّن بمكوّناتها وتُعرض للمستخدم كاملة.
2. **مراجعة آلية بثماني قواعد حتمية + عتبات بشرية آلية**: النموذج اللغوي يشرح ولا
   يُعدّل الأرقام — قابلية تدقيق كاملة لقرار الخطورة.
3. **حلقة HITL ذاتية التغذية**: التصحيح يتحول تلقائياً إلى مثال قياسي للاستخلاص
   اللاحق، مع قياس أثره باختبار A/B مزدوج (Wilcoxon/Wilcoxon + Cohen's d).
4. **بروتوكول تقييم يرفض النشر قبل الحقيقة**: النظام يبنى ليقول «غير مُملأة» بدل
   إنتاج رقم مضلّل — أي أن صدق القياس جزء من التصميم لا من التقرير.
5. **تدفّق مقاوم للفشل**: أدوات تفشل، مزوّد نماذج ينقطع، قاعدة تُقفل، ونموذج تضمين
   غائب — في كل حالة سلوك معلن ومختبر (11 اختبار فوضى) لا انهيار.

## 5) نتائج القياس المنشورة في هذا الإصدار (وحدودها)

كل الأرقام أدناه مقيسة فعلياً في **وضع Mock** ومُصدَّرة في `results/`، وهي **حدود
دنيا** (بلا شبكة ولا نماذج حقيقية) كما يُصرَّح في التقريرين نفسهما:

- `results/benchmark.md`: بدء التشغيل ≈ 363 ms · محرك التقييم ≈ 41.5 ألف ثغرة/ث ·
  خط كامل ≈ 751 ms (~37.5 ألف رمز تقديري) · فهرسة RAG ≈ 21 ms · استعلام ≈ 1.14 ms.
- `results/load_test.md`: 100 طلب/10 متوازية ← p50 48.8 / p95 89.1 / p99 102.2 ms
  بنجاح 1.0 · وإنتاجية فحص تسلسلي ≈ 105 فحص/دقيقة (Mock).

**لا توجد** في هذا المستودع أي نتيجة جودة (Precision/κ/AC1) — لأن الحقيقة المرجعية
اليدوية لم تُعبّأ بعد، والبروتوكول يمنع ذلك صراحة.

## 7) المعروف والمقيّد (مدفوع إلى v2)

- الحقيقة المرجعية (12 تطبيقاً) بانتظار تقييم خبيرين — التجربة جاهزة ومُختبرة
  السباكة، والنتائج تُولَّد آلياً عند التعبئة.
- حدّ المعدل في الذاكرة (لكل عملية) — Redis عند التوسع الأفقي.
- JWT بلا قائمة إبطال (logout منطقي) — كافٍ لعملية واحدة.
- `sentence-transformers` غير مثبت في بيئة التسليم ⇒ RAG يعمل بـ TF-IDF؛ الفرق
  كمّي في الجودة ويُقاس (RQ4) لا يُدّعى.
- استعلام SQLite المتزامن يحدّ من التوازي الحقيقي للفحوص — طابور/قاعدة خارجية v2.
