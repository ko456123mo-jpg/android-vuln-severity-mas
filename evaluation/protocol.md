# بروتوكول التجربة / Evaluation Protocol (المرحلة 7)

> **الحالة:** البروتوكول جاهز؛ الحقيقة المرجعية (Ground Truth) **لم تُملأ بعد** —
> تُملأ يدوياً من خبراء اثنين (انظر §4) ثم تُشغَّل التجربة ويُحلَّل الناتج.
> لا يحتوي هذا المستودع أي رقم تجريبي مصطنع.

---

## 1) أسئلة البحث (RQs)

| RQ | السؤال | المقياس | مصدر البيانات |
|----|--------|---------|----------------|
| RQ1 | ما دقة **استخراج** الثغرات مقارنة بالحقيقة المرجعية؟ | Precision / Recall / F1 | matched vs GT |
| RQ2 | ما دقة **تقييم الخطورة** (النظام مقابل الخبير)؟ | Percent Agreement + Weighted κ (تربيعي) + Gwet's AC1 + فترات ثقة 95% | أزواج matched |
| RQ3 | هل تُحسّن مرحلة **المراجعة (Reviewer)** الاتفاق مع الخبير مقارنة بالتقييم وحده؟ | Δκ / ΔAC1 بين وضعي `scorer_only` و`full` | مقارنة أوضاع |
| RQ4 | هل تُحسّن **RAG** دقة الاستخراج والقرار؟ | P/R/F1 + κ في `no_rag` مقابل `full` | مقارنة أوضاع |
| RQ5 | هل تُحسّن **حلقة التغذية الراجعة** (Few-Shot من تصحيحات بشرية) الاتفاق تدريجياً؟ | منحنى تعلم (اتفاق تراكمي عبر التصحيحات) + اختبار A/B مزدوج (t/Wilcoxon + Cohen's d) عند ≥ 20 تصحيحاً | تصحيحات HITL + `no_feedback` مقابل `full` |

## 2) العينة

12 تطبيقاً مفتوح المصدر معروف الضعف (قائمة `evaluation/dataset/apps.yaml`):
DIVA · InsecureBankv2 · UnCrackable L1-3 (OWASP MASTG) · AndroGoat · InsecureShop ·
OVAA · DVBA · Vuldroid · MSTG Hacking Playground · Sieve.
التنوّع مقصود: قطاعات (بنكي/تجارة/أداة)، حساسية بيانات، وأسطح MASVS مختلفة.

> ملاحظة تشغيلية: ملفات APK الفعلية توضع في `data/apks/<apk_file>` قبل التشغيل
> الحقيقي (أدوات MCP الحقيقية تقرؤها؛ وضع Mock لا يقرؤها — انظر §6).

## 3) الأوضاع التجريبية (عامل التحكم)

```
python evaluation/run_experiment.py --mode full        --apps diva,insecurebankv2
python evaluation/run_experiment.py --mode scorer_only --apps diva,insecurebankv2   # RQ3
python evaluation/run_experiment.py --mode no_rag      --apps diva,insecurebankv2   # RQ4
python evaluation/run_experiment.py --mode no_feedback --apps diva,insecurebankv2   # RQ5
```

- `full`: خط الأنابيب كاملاً (RAG + Reviewer + Few-Shot كما في الإنتاج).
- `scorer_only`: عقدة Reviewer تتخطى (كل التقييمات تبقى `pending`) — RQ3.
- `no_rag`: Extractor يستخدم كتلة `knowledge_base` كاملة (سلوك المرحلة 3) — RQ4.
- `no_feedback`: Scorer يتجاهل أمثلة `feedback_examples` — RQ5.

## 4) الحقيقة المرجعية (Ground Truth)

1. خبيران أمن تطبيقات مستقلان يقيّمان **كل ثغرة** في كل تطبيق على حدة.
2. كل خبير يسجّل: العنوان، CWE، فئة MASVS، خطورة (Critical/High/Medium/Low)،
   درجة متصلة 0–10 (تُستخدم للفحص الوصفي لا للاتفاق الفئوي).
3. الخلافات تُحلّ بمراجع ثالث (بند §4.4) — القرار النهائي `severity_expert`.
4. تُملأ ملفات `evaluation/dataset/ground_truth/<app_id>.json` — القالب جاهز
   مع `"filled": false`؛ لا تُعدّ التجربة صالحة قبل تعيينه `true` لكل تطبيق.

**صيغة المطابقة matched (موثقة — تُستخدم في المقاييس):**
ثغرة النظام تُطابَق مع ثغرة الخبير بـ CWE أولاً؛ عند غياب CWE على أحد الطرفين
يُستخدم تطابق العنوان المطبَّع (حروف صغيرة، إزالة رموز). كل عنصر يُطابَق مرة واحدة
(الجشع بترتيب ورود النظام)، وغير المطابَق = FP (للنظام) أو FN (للخبير).

## 5) المقاييس والإجراءات الإحصائية

> التفصيل الكامل (البدائل المرفوضة، صيغ الحساب، الأمثلة اليدوية، خريطة المقياس→الاختبار)
> في `docs/evaluation_protocol.md`.

- **RQ1:** `precision_recall_f1(tp, fp, fn)` لكل تطبيق + المتوسط الحسابي الماكروي
  عبر التطبيقات، مع فترة ثقة بووتستراب (95%) للـ F1 الماكروي.
- **RQ2:** على الأزواج المطابقة: Percent Agreement، Weighted Cohen's κ
  (أوزان تربيعية `w_ij = (i−j)²/(K−1)²`، ترتيب: Low<Medium<High<Critical)،
  Gwet's AC1 (صيغة Gwet 2008 للانتشار غير المتوازن)، مصفوفة التباس 4×4،
  وفترات ثقة 95% لكل مقياس عبر **10,000** إعادة معاينة (percentile method،
  بذرة 42 لإعادة الإنتاج). التفسير بسلّم Landis & Koch.
- **RQ3/RQ4:** فروق المقاييس بين الأوضاع على نفس التطبيقات (تحليل وصفي للفروق؛
  مع عدد تطبيقات ≥ 10 يُضاف اختبار مزدوج غير معلمي على قيم كل تطبيق).
- **RQ5:** (أ) منحنى التعلم: الاتفاق التراكمي بين خطورة النظام والخطورة المصحَّحة
  البشرية بترتيب التصحيحات التصاعدي (من جدول `corrections` مباشرة).
  (ب) A/B مزدوج عند ≥ 20 تصحيحاً: `paired t-test` + `Wilcoxon signed-rank` +
  `Cohen's d` لتأثير إدراج الأمثلة (يُعالَج كل زوج مطابق كوحدة قياس).
- **الحالة المنحلّة (0/0):** إذا كان تقييم أحد الطرفين ثابتاً بلا تباين، تكون κ
  غير معرّفة رياضياً؛ اصطلاحنا الموثق: تطابق تام ⇒ κ=1، وإلا κ=0 — وتُذكر
  الحالات المنحلّة في التقرير. (اكتُشف عملياً: sklearn يعيد NaN — عالجناه صراحةً).

## 6) إجراءات التشغيل

```bash
# 0) فهرسة RAG أولاً
EMBEDDING_MOCK_MODE=1 python scripts/ingest_knowledge.py

# 1) فحص تجريبي (Mock كامل — التحقق من السباكة بلا نتائج)
LLM_MOCK_MODE=1 MCP_MOCK_MODE=1 EMBEDDING_MOCK_MODE=1 \
  python evaluation/run_experiment.py --mode full --apps diva --dry-run

# 2) التشغيل الحقيقي (نماذج MCP حقيقية + APK موضوع في data/apks/)
python evaluation/run_experiment.py --mode full --apps diva,insecurebankv2

# 3) التحليل والتقارير
python evaluation/analyze_results.py --input results/ --output results/REPORT.md
python evaluation/analyze_feedback.py            # بعد ≥ 20 تصحيحاً بشرياً
```

مخرجات خام لكل (وضع، تطبيق) في `results/<mode>/<app_id>.json` — JSON فقط،
بلا أرقام مشتقة خارج `analyze_results` (فصل الخام عن المشتق).

## 7) التهديدات للصلاحية (Threats to Validity)

- **داخلية:** بيانات Mock في الفحوص التجريبية قد تُخفي انهيار سباكة حقيقي —
  عولج بإبقاء وضع Mock للتشغيل الآلي فقط، والتجربة الفعلية تعمل على APKs حقيقية.
  اختلاف إصدارات الأدوات/النماذج عبر التشغيلات موثّق في ملف كل تشغيل.
- **خارجية:** عيّنة سهلة القصد (تطبيقات مصممة للضعف) لا تمثل السوق الواقعي؛
  التعميم محدود ويُذكر صراحةً.
- **بنائية:** «الخطورة» مفهوم متعدد الأبعاد؛ اختزاله إلى فئتين-ترتيبية يفقد
  السياق (يُعالج جزئياً بالدرجة المتصلة في GT). اتفاق خبراء على قائمة CWE
  نفسها يميل لتضخيم Precision (يُخفف بالمراجعة الثالثة).
- **إحصائية:** عيّنة صغيرة (12 تطبيقاً × ~12 ثغرة) ⇒ فترات ثقة عريضة ومقارنات
  أوضاع وصفية أساساً؛ تكرار التشغيل 3 مرات لكل وضع لنمذجة تباين النماذج.

## 8) الأخلاقيات وإعادة الإنتاج

- لا استهداف لأي تطبيق إنتاجي؛ كل العينة تطبيقات مفتوحة الغرض تعليمي.
- كل تجربة تُولّد: معرف فحص، إصدار قاعدة `rule_version`، معرّفات النماذج،
  وبذور العشوائية (البووتستراب seed=42 ثابت).
- الكود المصدري للنظام كاملاً مع الاختبارات (كل مقياس في هذا البروتوكول مُختبَر
  بأمثلة محسوبة يدوياً في `tests/unit/test_metrics.py`).
